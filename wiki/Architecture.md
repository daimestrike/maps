# Архитектура

Одно приложение Next.js 16 (App Router) обслуживает и интерфейс, и API. Отдельного бэкенда нет. Данные — в PostgreSQL через Prisma. Состояния в памяти процесса нет, поэтому приложение можно запускать в нескольких экземплярах за балансировщиком.

```
браузер
  │  HTML страниц (server components) + fetch к /api/*
  ▼
Next.js (один процесс)
  ├── src/app/…            страницы и маршруты API
  ├── src/components/…     клиентские компоненты (карта, панели, формы)
  └── src/lib/…            общий слой: сессии, валидация, обёртка API, БД, геокодер
  ▼
Prisma Client → PostgreSQL
```

## Структура каталогов

```

  error.tsx                экран «Сервис временно недоступен» с кнопкой повтора
  globals.css              оформление интерфейса
  store-panel.css          оформление карточки магазина
  api/auth/[action]/       register | login | logout | me
  api/stores/              список и создание
  api/stores/[id]/         карточка и редактирование
  api/stores/[id]/comments/  чтение и добавление комментариев
  api/geocode/             координаты по адресу (офлайн)
  api/health/              проверка живости для Docker

src/components/

  Map.tsx                  Leaflet, кластеризация, контуры регионов

  AddStorePanel.tsx        форма добавления магазина

src/lib/

  db.ts                    единственный экземпляр Prisma Client

  geocode.ts               офлайн-геокодер по каталогу
```

## Ключевые решения

**Сессии, а не JWT.** Токен — 32 случайных байта, в cookie `x5_session` (HttpOnly, SameSite=Lax, срок 7 дней). В базе хранится только SHA-256 от токена, так что утечка дампа не даёт войти. Вход отзывает предыдущую сессию того же браузера и заодно подчищает истёкшие. Логика собрана в `src/lib/auth.ts` — при переходе на SSO заменяется этот файл, остальной код не трогается.

**Одна обёртка на все эндпоинты.** `endpoint()` из `src/lib/http.ts` оборачивает каждый маршрут: проверяет `Origin` у любого не-GET запроса, переводит `HttpError`, ошибки Zod и конфликт уникальности Prisma (P2002) в аккуратный `{error: "…"}` с нужным кодом, а всё неожиданное — в 500 без деталей наружу. Тело читается через `body()` с жёстким лимитом 16 КБ.

**Валидация только через Zod.** Все схемы — в `src/lib/validation.ts`, руками ничего не парсится. Сообщения об ошибках сразу на русском и показываются пользователю как есть.

**Вся карта загружается одним запросом.** `GET /api/stores` возвращает минимальный набор полей по всем магазинам, дальше фильтрация и поиск идут на клиенте. При 25 680 записях это работает; предел обсуждается в [[Limitations]].

**Поиск двухуровневый.** Эндпоинт умеет серверный поиск через `?search=`, но интерфейс его не использует: `Workspace` фильтрует уже загруженный массив, поэтому набор текста не создаёт запросов. Серверный поиск остаётся для API-клиентов.

**Карта не зависит от интернета.** Контуры регионов лежат в `public/`, слой тайлов отключается на сборке через `NEXT_PUBLIC_TILE_URL=off`. Маркеры добавляются в `markerClusterGroup` с `chunkedLoading`, чтобы не блокировать поток.

## Поток данных на рабочем экране

1. `src/app/page.tsx` — серверный компонент: читает cookie, при отсутствии сессии делает `redirect("/login")`, иначе рендерит `Workspace` с именем пользователя.
2. `Workspace` при монтировании запрашивает `GET /api/stores` (с `AbortController`) и держит массив в состоянии. Ошибка показывается с кнопкой «Повторить».
3. Ввод в поле поиска фильтрует массив локально. Список показывает первые 100 совпадений, карта — все.
4. Выбор магазина в списке или клик по маркеру → карта центрируется на точке (zoom 16) и открывается `StorePanel`.
5. `StorePanel` параллельно грузит карточку и первую страницу комментариев, затем позволяет редактировать поля и отправлять комментарии. Сохранённая карточка поднимается наверх через `onUpdated`, чтобы список и маркер обновились без перезагрузки.
6. `AddStorePanel` создаёт магазин; новая точка сразу добавляется в массив и выделяется.

## Безопасность на уровне маршрутов

Каждый эндпоинт вызывает `currentUser()` сам и отвечает 401, если сессии нет. Глобального middleware нет — это осознанно, чтобы не было маршрута, защищённого «по умолчанию» и незаметно выпавшего из-под проверки. Подробности — [[Security]].

Ответы API отдаются с `Cache-Control: no-store`. Заголовки `X-Content-Type-Options`, `X-Frame-Options: DENY` и `Referrer-Policy` задаются в `next.config.ts` для всех ответов, `X-Powered-By` отключён.
