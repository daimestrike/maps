# Эксплуатация

## Наблюдение

```sh
docker compose -f compose.prod.yaml ps                 # статусы и healthcheck
docker compose -f compose.prod.yaml logs -f app        # логи приложения
docker compose -f compose.prod.yaml logs -f db         # логи PostgreSQL
curl -s http://localhost:3000/api/health               # {"status":"ok"}
```

`/api/health` отвечает, пока жив процесс Next.js, и **не проверяет базу**. Живость базы смотрите отдельно:

```sh
docker compose -f compose.prod.yaml exec -T db pg_isready -U x5 -d x5_map
```

Если приложение живо, а база нет, пользователь увидит экран «Сервис временно недоступен» с кнопкой повтора.

## Резервное копирование

Единственное состояние — том `postgres_data`. Дамп:

```sh
docker compose -f compose.prod.yaml exec -T db \
  pg_dump -U x5 -d x5_map --format=custom > x5_map_$(date +%F).dump
```

Восстановление в чистую базу:

```sh
docker compose -f compose.prod.yaml exec -T db \
  pg_restore -U x5 -d x5_map --clean --if-exists < x5_map_2026-09-29.dump
```

Каталог магазинов восстанавливается и сам — из миграции и seed. Ценны именно **комментарии, пользователи и вручную добавленные или отредактированные магазины**. Дамп перед каждым обновлением с новыми миграциями — обязателен, откат схемы не предусмотрен.

Том нельзя удалять, если данные нужны: `docker compose down -v` стирает его безвозвратно.

## Пароли и доступ

**Пароль `admin@x5.local`** лежит в `.env` как `SEED_PASSWORD`:

```sh
grep SEED_PASSWORD .env
```

**Сброс пароля предустановленных пользователей.** Поменяйте `SEED_PASSWORD` в `.env` и перезапустите приложение — seed на старте перезапишет пароли трёх учётных записей (`admin@x5.local`, `ivan@example.com`, `anna@example.com`):

```sh
docker compose -f compose.prod.yaml up -d --force-recreate app
```

**Восстановления пароля для остальных пользователей нет** — ни писем, ни секретных вопросов. Если сотрудник забыл пароль, вариантов два: создать новый аккаунт или задать хеш напрямую в базе. Учётную запись с комментариями удалить нельзя (`ON DELETE RESTRICT`), сначала пришлось бы удалять комментарии, чего делать не стоит — авторство потеряется.

**Закрыть регистрацию** после создания нужных аккаунтов:

```sh
sed -i 's/^ALLOW_REGISTRATION=.*/ALLOW_REGISTRATION=false/' .env
docker compose -f compose.prod.yaml up -d --force-recreate app
```

**Завершить все сессии** — например, после перехода на HTTPS или при подозрении на утечку:

```sql
DELETE FROM "Session";
```

Все пользователи попадут на страницу входа при следующем запросе.

## Лимит попыток входа

10 попыток на email за 15 минут, счётчик общий для всех экземпляров приложения (таблица `AuthAttempt`). Считаются и вход, и регистрация — в том числе неудачные попытки регистрации с занятым адресом.

Снять блокировку досрочно:

```sql
DELETE FROM "AuthAttempt";
```

В таблице лежат SHA-256 от адресов, а не сами адреса, поэтому выборочно по email сбросить нельзя — только целиком.

## Разбор проблем

**После входа снова страница входа.** Почти всегда `COOKIE_SECURE=true` при доступе по HTTP: браузер не сохраняет cookie с флагом `Secure`. Поставьте `false` для HTTP или поднимите HTTPS.

**Все POST и PATCH отвечают 403 «Недопустимый источник запроса».** `APP_URL` не совпадает с адресом, по которому реально открывают сервис. Сравните до символа: схема, хост, порт. Частые случаи — зашли по IP, а в `APP_URL` домен; сменили `APP_PORT`, а `APP_URL` оставили с `:3000`.

**Карта пустая, маркеров нет.** Проверьте число магазинов:
```sh
docker compose -f compose.prod.yaml exec -T db psql -U x5 -d x5_map -tAc 'SELECT count(*) FROM "Store"'
```
Ноль — миграции или seed не прошли, смотрите логи `app` при старте. Число есть, а маркеров не видно — смотрите ошибки в консоли браузера.

**Карта серая, видны только контуры регионов и маркеры.** Так и должно быть в Docker-образе: слой тайлов отключён на сборке (`NEXT_PUBLIC_TILE_URL=off`). Чтобы вернуть подложку, пересоберите образ со своим сервером тайлов — [[Store Catalog|Store-Catalog]].

**Контейнер `app` не доходит до `healthy`.** Первый запуск идёт минуты: применяется 16-мегабайтная миграция каталога и импорт 25 680 записей. `deploy.sh` ждёт до 10 минут. Если не успевает — `docker compose -f compose.prod.yaml logs --tail=200 app`.

**Seed падает с `Set SEED_PASSWORD: 12–72 bytes`.** Пароль короче 12 символов или длиннее 72 байт. Помните, что русские буквы занимают по 2 байта.

**Seed падает с `prisma/data/stores.csv not found`.** Запускаете из неверного каталога (путь считается от текущего) или файл не выгружен из репозитория — он весит 13,5 МБ, убедитесь, что git-lfs или частичный клон его не пропустили.

**«Не удалось определить координаты».** Офлайн-геокодер ищет опору среди уже загруженных магазинов. На пустой базе и в районах, которых в каталоге нет, он не сработает — вводите широту и долготу руками.

**Медленный первый экран.** `GET /api/stores` отдаёт все 25 680 магазинов одним ответом. Это осознанный предел MVP, см. [[Limitations]].

## Регулярные задачи

| Что | Когда | Как |
|---|---|---|
| Дамп базы | По расписанию и перед каждым обновлением | `pg_dump` выше |
| Проверка `healthy` | Постоянно, внешним мониторингом | `GET /api/health` плюс `pg_isready` |
| Обновление образов | При выходе патчей PostgreSQL или Node | Пересобрать образ, `docker compose up -d` |
| Ревизия пользователей | Периодически | `SELECT email, name, "createdAt" FROM "User" ORDER BY "createdAt" DESC` |
| Чистка сессий | Не требуется | Истёкшие удаляются при каждом входе автоматически |

## Что сервис не делает сам

Ограничения по IP, аудит действий, ротацию логов, алерты, автоматические бэкапы — всё это настраивается снаружи: reverse proxy, cron, система мониторинга. Встроенный лимит попыток защищает один email, но не перебор по множеству адресов — см. [[Security]].
