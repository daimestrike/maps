# Справочник API

Базовый адрес — значение `APP_URL`. Все ответы — JSON, всегда с `Cache-Control: no-store`. Ошибка выглядит как `{"error": "текст на русском"}` — текст можно показывать пользователю напрямую.

## Общие правила

**Аутентификация.** Все эндпоинты магазинов, комментариев и геокодера требуют cookie сессии `x5_session`. Без неё — 401 `Войдите в систему`. В браузере cookie ставится автоматически после входа.

**Origin.** Любой запрос кроме GET обязан прислать заголовок `Origin`, совпадающий с origin из `APP_URL`. Иначе 403 `Недопустимый источник запроса`. Браузер подставляет его сам; в curl и скриптах указывайте вручную.

**Тело запроса.** Требуется `Content-Type: application/json` (исключение — logout, у которого тела нет). Иначе 415. Лимит тела — 16 КБ, больше — 413. Невалидный JSON — 400.

**Коды ошибок**

| Код | Когда |
|---|---|
| 400 | Не прошла валидация; текст — первое сообщение из схемы |
| 401 | Нет сессии, либо неверный email или пароль |
| 403 | Неверный `Origin`, либо регистрация закрыта |
| 404 | Магазин не найден, либо неизвестное действие в `/api/auth/…` |
| 409 | Нарушена уникальность — например, email или код магазина уже заняты |
| 413 | Тело больше 16 КБ |
| 415 | Не `application/json` |
| 422 | Координаты по адресу определить не удалось |
| 429 | Больше 10 попыток входа или регистрации по одному email за 15 минут |
| 500 | Внутренняя ошибка; подробности только в логах сервера |

## Аутентификация

### POST /api/auth/register

Создаёт пользователя и сразу открывает сессию. Возвращает 201.

```json
{ "name": "Иван Петров", "email": "ivan@x5.local", "password": "минимум-12-символов" }
```

Требования: имя 2–80 символов, email до 254 символов (приводится к нижнему регистру), пароль от 12 символов и не длиннее 72 байт — ограничение bcrypt.

Если `ALLOW_REGISTRATION=false` — 403 `Регистрация закрыта`.

Ответ: `{"id": "…", "name": "…", "email": "…"}`.

### POST /api/auth/login

```json
{ "email": "ivan@x5.local", "password": "…" }
```

200 и тот же объект пользователя. Неверная пара — 401 `Неверный email или пароль`, без подсказки, что именно не совпало. Сравнение пароля выполняется и для несуществующего email (против фиктивного хеша), чтобы время ответа не выдавало наличие учётной записи.

### POST /api/auth/logout

Без тела и без `Content-Type`. Удаляет серверную запись сессии и стирает cookie. Всегда `{"ok": true}`.

### GET /api/auth/me

Текущий пользователь или 401.

## Магазины

### GET /api/stores

Список для карты и поиска. Минимальный набор полей, сортировка по `code`.

Параметр `search` (до 200 символов) ищет подстроку без учёта регистра одновременно по `code`, `name`, `address` и `city`. Без параметра возвращаются все 25 680 записей.

```json
[ { "id": "catalog_E221", "code": "E221", "name": "13919-Пятерочка",
    "address": "452757, Башкортостан респ., …", "city": "Туймазы г.",
    "latitude": 54.602464, "longitude": 53.70178 } ]
```

### GET /api/stores/:id

Полная карточка: обязательные поля плюс `region`, `status`, `openingHours`, `coordinatesApproximate` и все справочные поля (`territory`, `macroregion`, `division`, `cluster`, `cfo`, `costCenter`, `sapPlant`, `formatCode`, `formatName`, `legalEntity`, `metro`). Незаполненные справочные поля приходят как `null`. Неизвестный `id` — 404.

### POST /api/stores

Создаёт магазин. 201 и созданная запись.

```json
{ "code": "E999", "name": "Новый магазин", "region": "Москва г.", "city": "Москва г.",
  "address": "101000, Москва г., Мясницкая ул., Дом 1", "status": "Активен",
  "openingHours": "08:00 - 23:00", "latitude": 55.7558, "longitude": 37.6173 }
```

Ограничения: `code` до 80 символов, `name` до 200, `address` до 1000, `city` и `region` до 200, `openingHours` до 200 (можно `null`), `status` обязателен.

Координаты можно **не передавать** — тогда они будут вычислены офлайн-геокодером, а магазин получит `coordinatesApproximate: true`. Передавать нужно либо обе, либо ни одной — иначе 400. Если геокодер ничего не нашёл — 422 `Не удалось определить координаты. Укажите их вручную.`

Занятый `code` — 409.

### PATCH /api/stores/:id

Полное обновление карточки: ожидаются все поля, что и в POST, но координаты **обязательны**. Любое успешное сохранение выставляет `coordinatesApproximate: false` — считается, что человек подтвердил точку.

## Комментарии

### GET /api/stores/:id/comments

Страница по 50 записей, от старых к новым.

```json
{ "items": [ { "id": "…", "text": "…", "createdAt": "2026-09-29T08:15:00.000Z",
               "user": { "id": "…", "name": "Иван (демо)" } } ],
  "nextCursor": "id-последнего-комментария-или-null" }
```

Следующая страница — `?cursor=<nextCursor>`. Курсор, не принадлежащий этому магазину, — 400 `Некорректная страница`. Кроме `id` и `name` автора никакие поля пользователя не отдаются.

### POST /api/stores/:id/comments

```json
{ "text": "Что важно знать коллегам" }
```

201 и созданный комментарий вместе с автором. Текст: 1–2000 символов после обрезки пробелов. **Автор берётся только из сессии** — передать чужой `userId` невозможно, поле просто не читается.

## Прочее

### POST /api/geocode

Координаты по адресу без интернета.

```json
{ "address": "452757, Башкортостан респ., Туймазы г., Чапаева ул., Здание 8а",
  "city": "Туймазы г.", "region": "Башкортостан респ." }
```

Ответ: `{"latitude": …, "longitude": …, "source": "почтовому индексу", "approximate": true}`. Поле `source` — по чему нашли (`почтовому индексу`, `городу` или `региону`), интерфейс подставляет его в сообщение. Ничего не нашлось — 422. Алгоритм описан в [[Store Catalog|Store-Catalog]].

### GET /api/health

`{"status": "ok"}` без авторизации. Используется в healthcheck Docker. Состояние базы **не проверяет** — отвечает, пока жив процесс Next.js.

## Пример: полный сценарий через curl

```sh
BASE=http://localhost:3000

# вход, cookie сохраняется в файл
curl -s -c cookies.txt -X POST "$BASE/api/auth/login" \
  -H "Origin: $BASE" -H 'Content-Type: application/json' \
  -d '{"email":"admin@x5.local","password":"ChangeMe-Demo-2026!"}'

# поиск
curl -s -b cookies.txt "$BASE/api/stores?search=Туймазы"

# комментарий
curl -s -b cookies.txt -X POST "$BASE/api/stores/catalog_E221/comments" \
  -H "Origin: $BASE" -H 'Content-Type: application/json' \
  -d '{"text":"Проверил вывеску, всё на месте"}'

# выход
curl -s -b cookies.txt -X POST "$BASE/api/auth/logout" -H "Origin: $BASE"
```
