# X5 · Внутренняя карта магазинов

Компактный MVP по ТЗ: Next.js App Router + React + TypeScript, Leaflet/OpenStreetMap, Prisma и PostgreSQL. Один процесс Next.js обслуживает интерфейс и API. Это прототип для X5, без официальных бренд-материалов и интеграций с корпоративными системами.

## Возможности

- Самостоятельная регистрация, вход по email/паролю, выход; сессии на 7 дней в PostgreSQL.
- Карта с группировкой маркеров, масштабированием и перемещением.
- Поиск без учёта регистра по коду, названию, адресу и городу; выбор результата центрирует карту и открывает карточку.
- Карточка: код, название, адрес, город, регион, статус.
- Комментарии с автором и временем, сохранение в БД, хронологический порядок и страницы по 50 записей. Кнопка «Обновить» загружает актуальные комментарии.
- Адаптивный интерфейс на русском; выбор магазина также доступен через список.

## Локальный запуск

Требуются Node.js 22+, npm и Docker с Compose. Из папки проекта:

```sh
cp .env.example .env
npm ci
docker compose up -d --wait
npm run db:migrate
npm run db:seed
npm run dev
```

Откройте http://localhost:3000. Зарегистрируйте свой аккаунт либо используйте `ivan@example.com` / `anna@example.com` и пароль из `SEED_PASSWORD` в `.env` (в примере `ChangeMe-Demo-2026!`). Seed создаёт 8 **вымышленных демонстрационных** магазинов. Коды, адреса и координаты не являются подтверждёнными данными X5.

Seed можно запускать повторно: существующие магазины и пользователи не меняются, пароли не сбрасываются. `SEED_PASSWORD` нужен только при запуске seed. Если у вас уже есть PostgreSQL, пропустите Docker и укажите свой `DATABASE_URL`.

Для проверки production-сборки локально:

```sh
npm run build
npm run check
npm start
```

`COOKIE_SECURE=false` нужен для локального HTTP, в том числе `npm start`. Порт по умолчанию 3000; при его изменении обновите `APP_URL`. `docker compose stop` останавливает БД, данные сохраняются в именованном томе. Не удаляйте том, если нужны данные.

## Проверка MVP

При запущенном приложении и доступной БД:

```sh
npm run test:integration
```

Тест создаёт временных пользователей и магазин, проверяет регистрацию и вход, запрет анонимного доступа и чужого Origin, поиск, ограничения текста, невозможность подменить автора, сохранение в PostgreSQL, чтение другим пользователем, страницы комментариев и отзыв сессии при выходе. Затем удаляет собственные тестовые записи. Выполняйте в локальной/тестовой БД с открытой регистрацией.

Ручная проверка: войдите Иваном, найдите `DEMO-001`, откройте карточку, отправьте комментарий, обновите страницу и снова выберите магазин. Во втором браузере войдите Анной: комментарий должен быть виден с автором Иваном. Проверьте выбор маркера, группировку при уменьшении масштаба и мобильную ширину.

## Данные и API

`prisma/schema.prisma` — модели User, Session, Store, Comment, AuthAttempt. Начальная миграция включена. `prisma/seed.ts` — примеры загрузки магазинов через уникальный `code`. Замените демонстрационный набор вашим выгруженным списком: name, code, address, city, region, latitude, longitude, status. Координаты должны быть заранее проверены (широта −90…90, долгота −180…180); онлайн-геокодирования нет. Демонстрационные записи сами при импорте не удаляются.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/register` | `{name,email,password}` |
| POST | `/api/auth/login` | `{email,password}` |
| POST | `/api/auth/logout` | Отзыв текущей сессии |
| GET | `/api/auth/me` | Текущий пользователь |
| GET | `/api/stores?search=…` | Поля для карты/поиска |
| GET | `/api/stores/:id` | Карточка |
| GET | `/api/stores/:id/comments?cursor=…` | `{items,nextCursor}` |
| POST | `/api/stores/:id/comments` | `{text}`; автор из сессии |

Все API магазинов требуют cookie-сессию. Для POST нужен `Content-Type: application/json` (кроме logout) и `Origin`, совпадающий с `APP_URL`. В браузере Origin устанавливается автоматически. Ошибки: `{error: "…"}`. Пароли: минимум 12 символов, максимум 72 байта, bcrypt с cost 12. Cookie: HttpOnly, SameSite=Lax, Secure через настройку. В БД хранится хеш случайного токена сессии. Пользовательский текст React отображает как текст; HTML не исполняется.

## GitLab и сервер

Загрузите **содержимое этой папки** в репозиторий. `.env`, `node_modules`, `.next` исключены, `.env.example`, миграции и `package-lock.json` входят в проект. `.gitlab-ci.yml` собирает приложение и запускает интеграционный тест с отдельной PostgreSQL. CI использует одноразовые тестовые учётные данные.

На сервере установите зависимости через `npm ci`, задайте переменные окружения, примените `npm run db:migrate`, выполните `npm run build`, запустите `npm start` под менеджером процессов. При развёртывании задайте `APP_URL=https://ваш-внутренний-домен`, `COOKIE_SECURE=true`, уникальные учётные данные БД. Используйте HTTPS через reverse proxy и внутреннюю сеть/VPN. Публичная регистрация не проверяет принадлежность email компании: установите `ALLOW_REGISTRATION=false` после создания аккаунтов либо ограничьте доступ сетью. Не запускайте демонстрационный seed в рабочей базе без необходимости.

Встроенный лимит входа/регистрации — 10 попыток на email за 15 минут в общей БД. Для доступного из интернета сервера добавьте ограничение запросов по IP на доверенном reverse proxy; встроенный лимит не защищает от перебора разных email. Делайте резервные копии PostgreSQL. После перехода на HTTPS ранее созданные локальные сессии лучше завершить.

## Границы MVP

Карта загружает все магазины одним запросом с минимальными полями; маркеры группируются и добавляются порциями. Список выводит первые 100 совпадений, карта — все совпадения. Перед загрузкой всей реальной сети измерьте время загрузки и работу браузера; следующий шаг при необходимости — загрузка по границам карты и серверный поиск. Комментарии загружаются отдельно при выборе магазина, realtime отсутствует.

Тайлы поступают с публичного сервера OSM, нужен интернет. Атрибуция сохранена, массового скачивания и офлайн-кеша нет. Для корпоративной нагрузки выберите подходящий источник тайлов с учётом [политики OpenStreetMap](https://operations.osmfoundation.org/policies/tiles/). Список магазинов и комментарии не передаются OSM, но запросы тайлов раскрывают область просмотра.

SSO, роли, редактирование/удаление комментариев, восстановление пароля, проверка email и админ-панель в MVP не входят. Авторизация выделена в `src/lib/auth.ts`, чтобы её можно было заменить.

Стек и команды сверены с документацией [Next.js](https://nextjs.org/docs) и [Prisma Migrate](https://www.prisma.io/docs/orm/v6/prisma-migrate/workflows/development-and-production).

Для `@prisma/config` закреплён `deepmerge-ts@8.0.0` через npm overrides: исправление [GHSA-ggr8-5vv4-36mx](https://github.com/advisories/GHSA-ggr8-5vv4-36mx). Совместимость проверяется командами генерации, миграции, seed и сборки.
